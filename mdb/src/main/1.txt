这个加锁 到底哪些地方需要加 怎么加;
首先是 查询的时候; flush的时候; checkpoint的时候;
查询的时候按mysql的思想来说 加行级读和写锁就可以了;
flush的时候按mysql的思想了来说, 其实也是加行级写锁就可以了;
checkpoint的时候按道理也是加行级读锁就好了; 然后有锁表的时候吗;应该有加行级读锁的地方

查询  表读锁; 行读锁, add remove 表读锁;加行写锁;
flush 表读锁; 行写锁;
checkpoint 表读锁;行读锁;
checkpoint 可能在batch 批量执行的时候需要加表写锁; 将表锁住 不能让其他人操作;

只有两个地方会往数据库里面写入;一个是flush 一个是 checkpoint;
如果checkpoint 还不能加行写锁 他要加了行写锁 那查询的时候会卡;会很影响查询;

假设现在什么锁都不加; 查询的地方 get add remove; 会有什么问题;
会多次重复运行 get add remove; 导致超查 超删 超写; 所以得加行锁控制住;

flush的时候不加锁会怎么样;
flush 其实应该默认不会有get add remove 过来了; 当然过来也有可能;为了get add remove的时候判断玩家不在线不能加载;所以flush某个玩家的时候;
其玩家的所有操作应该都不能操作; 不然 我这边刚flush掉 你这边开始加 查 删; 但是这样也会导致业务线程卡主;
应该是 我那边先标记为 flush 然后 get add remove 直接就判断不能操作了;
标记为flush 然后再延迟1秒以后flush (防止get add remove刚好判断完 但是后面的逻辑还没执行;); flushfinish以后再将logic的mdbplayeronline删除掉;再通知 lb删除; 删除的时候和再上线这个先不管 反正能处理;
