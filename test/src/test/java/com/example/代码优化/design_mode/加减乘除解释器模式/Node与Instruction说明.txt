表达式解释器中的 Node 和 Instruction

先记住这两个概念：

Node 描述表达式的结构和含义。
Instruction 描述虚拟机运行时要执行的动作。


一、Node：把表达式组成一棵树

例如表达式：

    1 + 2 * 3

它的结构是：先算 2 * 3，再把结果加到 1 上。
Parser 会把这个结构保存成 Node 树：

    ADD
    ├── 1
    └── MULTIPLY
        ├── 2
        └── 3

树上的每个节点表示一部分表达式：

    数字、变量、方法调用是一种节点。
    一元运算符会有一个子节点。
    二元运算符会有左、右两个子节点。

Node 还会带着编译期算出的类型。例如：

    1 + 2       类型是 NUMBER
    1 > 2       类型是 BOOLEAN

编译器可以沿着 Node 树检查运算符和操作数的类型是否匹配。


二、Instruction：把树翻译成运行步骤

上面的 Node 树会被编译成虚拟机指令：

    PUSH 1
    PUSH 2
    PUSH 3
    MULTIPLY
    ADD

执行器按顺序执行这些指令：数字压入 double 栈，MULTIPLY 从栈中取出两个数相乘，
ADD 再取出两个数相加。

源码中的运算符会成为一条对应的运算指令。例如：

    <   -> OperatorInstruction(LT)
    >=  -> OperatorInstruction(GE)

它们使用同一个 Java 指令类，但各自保存不同的运算符枚举值。


三、为什么要分成两步

Node 保留表达式的树形结构，适合做类型检查和决定控制流。
Instruction 是较低层的执行步骤，适合虚拟机用程序计数器和 double 栈快速运行。

Node 只用于编译阶段。表达式编译完成后，最终保存的是指令数组；每次 evaluate 时执行
指令数组，不再遍历 Node 树。


四、短路逻辑为什么会变成跳转指令

对于：

    A && B

Node 会保留这是一个逻辑与表达式。编译器把它生成短路指令：

    计算 A
    如果 A 为 false，跳到 false 分支
    计算 B
    如果 B 为 false，跳到 false 分支
    压入 true
    跳过 false 分支
    false 分支：压入 false

所以 && 和 || 虽然在 Node 树中是逻辑运算符，执行时会被编译成条件跳转和布尔压栈等
多条指令，而不是一条普通的 AND 或 OR 指令。这样右侧表达式才能按需执行，实现短路。


五、整体流程

    表达式文本
        -> Lexer 产生 Token
        -> Parser 构造并检查 Node 树
        -> ExpressionCompiler 把 Node 树编译为指令数组
        -> Expression 执行指令数组

可以把 Node 理解为表达式的结构说明，把 Instruction 理解为虚拟机执行这份说明时要做的
具体动作。


六、这里具体用了哪些算法

这不是单独一种算法，而是把几种常见算法串成一条编译和执行流程：

1. 词法分析：从左到右扫描字符，切成 Token。

   例如，<= 会作为一个完整 Token 识别；&& 也会作为一个完整 Token 识别。
   多字符运算符按最长匹配处理，单独的 =、&、| 会报错。

2. 语法分析：递归下降解析，并用不同解析层级表达优先级。

   解析入口按优先级从低到高调用：

       parseOr
           -> parseAnd
               -> parseEquality
                   -> parseComparison
                       -> parseAdditive
                           -> parseMultiplicative
                               -> parseUnary
                                   -> parsePrimary

   例如，乘法在 parseMultiplicative 这一层先组合成子树，随后才回到加法层，
   因而 1 + 2 * 3 会得到 ADD(1, MULTIPLY(2, 3))。

   这种写法叫递归下降解析。当前实现没有用调度场算法直接生成后缀表达式。

3. 类型检查：构造 AST 节点时检查运算符的输入类型，并计算结果类型。

   例如，ADD 要求两个子节点都是 NUMBER；AND 要求两个子节点都是 BOOLEAN。
   错误会在编译阶段报告，合法表达式的 evaluate 阶段不用重复检查类型。

4. AST 编译：从根节点向下遍历，把树翻译为栈式指令。

   普通二元运算按“左子树、右子树、运算指令”的顺序生成指令。
   这类似后序遍历，也让虚拟机可以用操作数栈执行。

5. 跳转地址回填：逻辑短路需要跳转到稍后才确定的位置。

   编译器先输出一个目标地址未确定的跳转指令占位符，继续生成后面的指令，
   确定分支位置后再把地址写回跳转指令。这种技术常称为回填。

6. 指令执行：用程序计数器和操作数栈运行字节码。

   普通指令执行后程序计数器加一；条件跳转和无条件跳转会把程序计数器改到目标位置。
   由于有条件跳转，&& 和 || 的右侧表达式可以在不需要时完全跳过。

因此可以把整体概括为：

    递归下降解析
        -> 类型化 AST
        -> AST 后序编译和跳转回填
        -> 基于 double 栈和程序计数器的虚拟机执行
