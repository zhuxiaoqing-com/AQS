顺时针（clockwise）和逆时针（counter-clockwise）的含义
这两个词是纯粹的观察视角描述，不依赖坐标系，全球统一：
顺时针：像时钟指针转动方向（从12点 → 1点 → 2点...）
逆时针：相反方向（从12点 → 11点 → 10点...）
它们只取决于你从哪个方向看平面：
从正面看时钟 → 顺时针
从背面透过玻璃看 → 看起来逆时针（但实际方向没变，只是视角翻转）
→ 顺时针/逆时针本身不随坐标轴变化，它只是“看起来像什么”的描述。


. 正方向（positive rotation）和反方向（negative rotation）的含义
这两个词是坐标系约定的一部分，会随着坐标系的手性（handedness）变化。
正方向 = θ > 0 时向量/物体转动的方向
反方向 = θ < 0 时转动的方向

坐标系类型,          手性判定规则（螺旋定则）,       正方向（θ > 0）旋转,           正方向看起来是,                常见系统/引擎示例,备注
右手坐标系,          右手大拇指沿 +轴，四指卷曲方向,       逆时针,                    逆时针,                数学/物理标准、OpenGL 世界坐标、Blender、Maya、MMDetection3D,最标准的学术约定
左手坐标系,          左手大拇指沿 +轴，四指卷曲方向,       顺时针,                    顺时针,                Unity、Unreal Engine、DirectX 默认,游戏引擎最常见
特殊情况,           y 轴向下（如很多2D屏幕坐标）,       可能反转视觉感受,           取决于 y 方向,               部分 UI/2D 游戏,y 向下会让“看起来”顺/逆反过来

正/反方向是会随着坐标系手性变化的：右手系正 = 逆时针，左手系正 = 顺时针。

为什么会这样约定？（核心原因）
    一切源于叉乘（cross product）和螺旋定则的统一：
    右手系：A × B 的结果方向用右手定则 → +z = x × y → 从 +z 看，x 到 y 逆时针
    左手系：A × B 用左手定则 → 从 +z 看，x 到 y 顺时针

旋转正方向必须和这个叉乘方向一致，否则法向量、角速度、扭矩等物理量会符号混乱。
数学家/物理学家先选了右手定则 + 逆时针正（因为叉乘在电磁学、力学里这样最方便）。
游戏引擎后来为了“前进 = +z”直觉 + DirectX 历史，选了左手 + 顺时针正。

总结一句话区分

顺时针 / 逆时针：看起来的方向，客观、不变，只取决于观察视角（从哪边看轴的正端）。
正方向 / 反方向：约定哪个是 θ > 0，会随坐标系手性变化：
右手系 → 正 = 逆时针（从 +轴端看）
左手系 → 正 = 顺时针（从 +轴端看）

所以当有人说“正旋转是逆时针”时，通常默认是右手坐标系；说“正旋转是顺时针”时，通常是左手坐标系（如 Unity 项目）。
