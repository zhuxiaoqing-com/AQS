    玩家收到pong以后，(clientCurrTime - pong.客户端时间)/2 就是RTT, 然后取服务器和客户端当前时间的差距;

    保存客户端和服务器的差距时间 = pong.serverTime + RTT/2 - currClientTime;

最近一直问AI，发现了一种更稳的方式,就是服务器怪物开始移动的时候还是发送怪物的开始移动时间,然后客户端有个固定延迟时间的全局参数,比如固定比服务器慢100ms;
const float interpolationDelay = 0.05f; // 50ms
void Update()
{
    float renderTime = serverNowTime - interpolationDelay;

    // 找到 renderTime 前后的两个快照
    MonsterSnapshot lhs, rhs;
    FindSnapshots(renderTime, out lhs, out rhs);

    float t = (renderTime - lhs.serverTime) /
              (rhs.serverTime - lhs.serverTime);

    Vector3 pos = Vector3.Lerp(lhs.position, rhs.position, t);
    transform.position = pos;
}
这样的话 比如开始移动的时候延迟是100ms,结束移动的时候延迟是50ms,按我老的方式的话，怪物就会多移动50ms，但是如果有固定延迟的话,只要服务器和客户端不超过固定延迟的情况下,
    就不会有怪物多移动的问题;

这个算是一个优化吧;

还有玩家移动，其他客户端应该就也弄个50ms延迟表现玩家移动来进行抗延迟处理;因为我就算计算了RTT，但是很有可能，网络的上下行延迟并不是一致的;
在“真实世界、尤其是手机网络”里：
👉 通常是「客户端 → 服务器（上行）」更慢、更抖
👉 服务器 → 客户端（下行）更快、更稳

    public void Pong(float t)
    {
        float curRtt = Time.time - t;
        float rate = 0.8f;
        NetworkManager.Instance.RTT = NetworkManager.Instance.RTT * rate + (1 - rate) * curRtt;
    }
